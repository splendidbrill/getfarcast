# Plan: Platform-Based Post Generation for Businesses

## Goal
Modify the post generation system to use user-provided JSON data for all platforms, determine which platforms are suitable for a particular business based on comprehensive criteria, and generate posts only for those suitable platforms.

## Current System Analysis
- The system uses deterministic channel matching in `channelMatcher.ts` based on ICP (demographics, psychographics, DISC profiles, industry, pricing).
- Supported platforms: Reddit, LinkedIn, Instagram, Hacker News, Product Hunt, X (Twitter), YouTube.
- Posts are generated for text-based platforms only (Reddit, LinkedIn, X, Hacker News, Product Hunt, Facebook).
- Visual platforms (Instagram, TikTok, YouTube) are excluded from post generation.

## Required Changes

### 1. Integrate Platform JSON Data
- **Action**: Load and parse the user-provided JSON files containing platform data.
- **Implementation**: Create a new module to load platform configurations from JSON files.
- **Location**: `src/lib/platforms/` directory.
- **Files to create/modify**:
  - `src/lib/platforms/loader.ts` - Function to load and validate platform JSON data.
  - `src/lib/platforms/types.ts` - TypeScript interfaces for platform data structure.

### 2. Enhance Platform Matching Logic
- **Action**: Replace or augment the current hardcoded matching rules with JSON-based criteria.
- **Criteria to consider**: "Best of everything" - comprehensive evaluation including industry fit, audience demographics, pricing model, content type suitability, engagement patterns, and business goals.
- **Implementation**: Update `channelMatcher.ts` to use JSON data for scoring platforms.
- **Algorithm**: For each platform, evaluate multiple factors (industry, audience age/income, DISC types, pricing tiers) and compute suitability score.
- **Files to modify**:
  - `src/lib/channelMatcher.ts` - Refactor to use JSON-driven matching instead of hardcoded rules.

### 3. Update Post Generation Pipeline
- **Action**: Ensure posts are generated only for platforms determined suitable by the new matching logic.
- **Implementation**: Modify `generate-playbook/route.ts` to use the enhanced matcher and filter posts accordingly.
- **Fallback**: Maintain minimum platform requirements (at least 3 text platforms) if no platforms score highly.
- **Files to modify**:
  - `src/app/api/generate-playbook/route.ts` - Update channel filtering logic.

### 4. Frontend Adjustments
- **Action**: Update UI to reflect the new platform selection and ensure post display works with filtered platforms.
- **Implementation**: Modify `PlaybookPosts.tsx` to handle dynamic platform lists.
- **Files to modify**:
  - `src/components/playbook/PlaybookPosts.tsx` - Update platform configs and filtering.

### 5. Validation and Testing
- **Action**: Add validation for platform JSON data and test the matching logic.
- **Implementation**: Create unit tests for platform matching and integration tests for post generation.
- **Files to create**:
  - `src/lib/platforms/__tests__/loader.test.ts`
  - `src/lib/__tests__/channelMatcher.test.ts`

## Platform JSON Data Analysis
- **Data Received**: Full JSON data for 25 platforms including Reddit, Twitter/X, TikTok, Instagram, YouTube, Facebook Groups, Threads, Hacker News, Product Hunt, Indie Hackers, Dev.to, GitHub, Discord, Slack Communities, Quora, WhatsApp/Telegram Groups, Medium/Hashnode, Podcast Guesting, Shopify App Store, Chrome Web Store, App Store/Google Play Store, AppSumo/Betalist, G2/Capterra, and Lobsters/Tildes.
- **Structure**: Each platform object contains:
  - `channel`: Platform name
  - `tier`: Priority level (1-5, where 1 is highest priority)
  - `channel_dna`: Platform characteristics (type, algorithm, audience, content formats, culture)
  - `fit_scoring_matrix`: Suitability criteria (best/worst product types, pricing, ICP signals, red flags)
  - `growth_mechanics`: CAC, timeframes, effort level, virality
  - `algorithm_playbook`: Posting strategies, timing, cadence
  - `content_system`: Winning content types, hooks, tone, CTAs
  - `community_outreach_playbook`: Engagement strategies
  - `business_stage_playbook`: Stage-specific tactics
  - `proof_of_play`: Real-world examples

## Enhanced Platform Matching Logic
- **Criteria Mapping**: Use "fit_scoring_matrix" to evaluate business suitability:
  - Compare business industry/product type against "best_product_types" and "worst_product_types"
  - Match pricing model with "best_pricing_models"
  - Evaluate ICP against "icp_match_signals" and "red_flags_skip_this_channel"
  - Consider "geographic_strength" for business location
- **Scoring Algorithm**: For each platform, compute suitability score based on:
  - Product type match (weight: 40%)
  - Pricing model alignment (weight: 20%)
  - ICP signals (weight: 20%)
  - Growth mechanics fit (effort level vs business stage) (weight: 10%)
  - Tier priority (weight: 10%)
- **Filtering**: Only select platforms with score above threshold and no red flags. Ensure at least 3 platforms for post generation.

## Expanded Platform Support
- **New Platforms**: Add support for all 25 platforms in the JSON data, beyond current 7.
- **Platform Categories**: Classify as text-based, visual, community-based, app marketplaces, etc. for appropriate post generation.
- **Content Adaptation**: Use "content_system" and "algorithm_playbook" from each platform's JSON to customize post generation prompts, hooks, tone, and CTAs.

## Dependencies
- JSON data structure validated and parsed correctly.
- Business data (industry, pricing, ICP) must be available for matching.

## Risks and Considerations
- JSON parsing errors if data is malformed.
- Performance impact from evaluating 25 platforms per business.
- Ensuring backward compatibility with existing LinkedIn/X/Reddit focus.
- Platform-specific content guidelines may conflict with current LLM prompts.
